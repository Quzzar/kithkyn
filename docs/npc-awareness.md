# Resident awareness

Initial capture and conversation grounding for [#187](https://github.com/Quzzar/kithkyn/issues/187).
This supplies recent evidence to existing conversations. It does not yet add autonomous
model-driven reactions, voice input, or durable intentions. The larger delivery plan is in
[npc-agency.md](npc-agency.md).

## What a resident knows

The server records observations on each loaded resident, with subject and source UUID/name,
dimension, last observed position, first/last game tick, expiry and a bounded occurrence count.

- **SEEN:** an approached player, visible potential threat, or witnessed injury.
- **EXPERIENCED:** the resident's own injury. A hidden attacker remains unidentified.
- **REPORTED:** words addressed to this resident by a player or their current villager partner.
- **HEARD:** an existing villager speech line overheard nearby.

Reports and overheard quotes are speech, not verified claims about the world. A report of a
dragon is not a dragon sighting. The briefing states this explicitly and quotes the text as
data. Speaker identity comes from the actual server entity, not a name or ID generated by a
model. Synthetic greeting cues and developer prompt replays do not become speech events.

Capture requires an awake, living observer, an identified non-invisible speaker/subject,
distance within sixteen blocks and an unobstructed line. Initial hearing deliberately uses
the same conservative unobstructed range; wall transmission, anonymous voices and sound
attenuation are not implemented. The shared `Witnesses` gate checks already-loaded terrain
before tracing, uses a spherical distance limit, and recognizes a target solid block without
allowing the old near-target wall tolerance. Existing wrongdoing also uses that gate.

Actual post-damage events supply injury evidence. Seeing the victim does not identify a
hidden attacker. New personal injury memories likewise withhold an unseen attacker's name;
existing saved memories are not rewritten. The existing immediate pain/opinion and native
combat rules remain in place. Recent evidence does not replace the personal log or village
planning snapshot.

Identified village blame now requires seeing both the incident and its culprit. Seeing only
an injured victim cannot attach an unseen player's UUID to a witness's durable memory or
subsequent reflection. Entity sight requires a clear ray even when an obstruction occupies
the same partial block as the subject's eyes; the solid-target exception is for block events.
Witnessed non-player deaths likewise name a killer only when each witness could identify
that killer. A visible victim's death is still remembered when its cause remains unknown.

## Limits and timing

Each resident keeps at most sixteen observations. Chat includes the six most recently
refreshed, with explicit provenance and last-seen time. Speech and injuries expire after
sixty game seconds, approached players after ten, and visible threats after three. Repeated
matching events within five seconds refresh one episode rather than append copies. Refreshes
do not advance the episode revision; future decisions must not treat each repeated sighting
as a new incident. Counts saturate at 999. Quotes are capped at 160 characters and names at 64.

Threat scans are staggered to at most once per second per resident. A scan or event fan-out
considers at most 24 matching entities. Across all dimensions of one server, each game tick
permits at most 32 spatial queries, 256 visibility checks and 128 delivered observations.
Each resident accepts at most eight deliveries per tick. Exhaustion omits evidence; it does
not claim the event was absent or substitute a fact. Global denied work is counted. Under
overload a resident can miss an event or a scan, and candidate truncation is conservative.

Perception itself never calls a model, starts conversation or chooses a movement/combat goal.
Existing player and villager conversations read the snapshot when they assemble a turn.
Automatic event-driven decisions and their inference budgets belong to #188. Awareness
stays session-local, and clears on dimension changes. Save/reload memory is part of #189.

## Verification and limits of the evidence

`./gradlew check` covers identity separation, provenance, exact expiry, clock rewind, bounded
storage/prompt size, repeated-event coalescing and shared work ceilings. The world fixture is
`./gradlew runResidentAwarenessVerification`. It uses `run/npc-awareness-verification`;
accept Minecraft's EULA there and configure its `config/kithkyn-common.toml` with
`general."Generate villages" = false` and `llm."Enable LLM?" = false` before running.

Read `[resident-awareness-verify] RESULT PASS`, not merely a successful Gradle exit. The
fixture exercises real walls, distance, sleeping/invisibility, post-damage callbacks, hidden
attacker attribution, player/villager speaker IDs, bystander speech, prompt inclusion,
repeated-event budgets, actual threat scans and expiry. It then measures 64 stationary
residents for 1,200 ticks and checks the outgoing-provider counter stays unchanged.

On 2026-10-21 that population made 3,840 spatial queries, 3,840 visibility checks and 3,840
observation deliveries, with zero extra model requests and no denied work in the population
phase. The separate repeated-speech burst exercised budget exhaustion.
That isolated population has no work simulation or dialogue generation. It is not a populated
village frame/tick benchmark or proof that the model will reliably use the evidence. Keep
#187 open for populated gameplay and model acceptance, and #192 for the full companion scenario.

The default-off [reaction experiment](npc-reactions.md) consumes these snapshots for bounded
choices. Awareness itself still makes no model calls; disabling reactions preserves that behavior.
